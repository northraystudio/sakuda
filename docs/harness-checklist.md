Generated by maruda setup. CI is strict by design — these are the
manual steps that turn it green and make the gates actually gate.

Completed during the yds → maruda migration (2026-09-20):

- [x] Commit `.claude/`, `CLAUDE.md`, `.github/`, `.gitleaks.toml`, `.semgrepignore` and push `main`
- [x] If re-running setup produced `*.new` files: diff, merge, delete them
- [x] Node: add `lint / typecheck / test` scripts to `package.json` (CI preflight fails without them)
- [x] Node: commit `pnpm-lock.yaml` (frozen-lockfile install requires it)
- [x] Write the first test with the first code PR — zero tests fail CI by design
- [x] After the first push: `setup.sh --protect` (requires repo ADMIN) so checks become required and actually block merges
- [x] Adjust CLAUDE.md commands if the defaults don't match your project
- [x] PR Agent: add the repository secret `OPENAI_KEY` — until set, the `PR Agent` workflow fails on every PR (advisory only, never a required check)

## Local invariants (do not regress)

- **Never add a `version:` input to `pnpm/action-setup`.** `package.json`
  declares `"packageManager": "pnpm@10.26.1"`, and the action throws
  `Multiple versions of pnpm specified` unless the two strings match exactly.
  The version is intentionally read from `packageManager` alone.
